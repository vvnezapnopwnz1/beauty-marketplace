# Backlog

Список фич и улучшений, сознательно отложенных на будущие итерации (чтобы не терялись). Добавляй сюда пункты из брейнштормов и дизайн-сессий. Короткая формулировка + ссылка на спеку / тикет, если есть.

## Профиль пользователя

- **Смена телефона через OTP** — редкая операция, нетривиальный флоу (OTP на новый номер, проверка занятости, опционально OTP на старый + logout everywhere). Сейчас в UI просто отображаем телефон без возможности менять. Отложено из спеки `2026-04-24-user-profile-design.md` (вопрос 4 → вариант A). Когда делать: когда появятся реальные юзеры и запросы из поддержки.
- ~~**Загрузка аватара пользователя**~~ → **Реализовано.** Реализованы S3-сервисы и эндпоинт `POST /api/v1/me/avatar` на бэкенде. На стороне мобильного приложения в личной информации (`profile-info.tsx`) подключена полноценная загрузка аватара через `expo-image-picker` с обновлением кэша React Query.
- **Портфолио мастера (Master Portfolio)** — расширенная галерея фоторабот мастеров. Каждое фото в портфолио должно быть не просто картинкой, а содержать текстовое описание, дату съемки, тип выполненной услуги и специальные маркеры-теги (например, «до стрижки», «после стрижки»). Требует разработки таблицы БД `master_portfolio_photos`, CRUD-эндпоинтов на бэкенде Go и интерфейса загрузки/просмотра в вебе и мобильном приложении.
- **Деприкация `GET /api/auth/me`** — фронтенд переехал на `/api/v1/me`, но старый эндпоинт оставлен для обратной совместимости. Нужно спланировать удаление: инвентаризация оставшихся вызовов, релиз-ноты, срок отключения и удаление кода в `auth`-контроллере/клиентах. Когда делать: после стабилизации `/me` и одного релизного цикла без обращений к старому маршруту.

## Роли и права

## Сеть салонов / филиалы

- **Управление филиалами (multi-location)** — у одного владельца может быть несколько точек (филиалов), каждая со своим дашбордом, мастерами, услугами и расписанием. Записи и данные между филиалами не смешиваются. Требует: сущность `SalonGroup` / `Chain` (группа салонов), UI переключения между филиалами, агрегированная аналитика по сети. На MVP достаточно sidebar-переключателя между салонами в `salon_members`. Когда делать: когда появятся первые владельцы с 2+ точками.
