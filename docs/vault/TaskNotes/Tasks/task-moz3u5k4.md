## Текущий флоу онбординга мастера (как работает сейчас)

1. **Точка входа**: Пользователь (неавторизованный) нажимает кнопку «Войти / Зарегистрироваться» на лендинге `/for-masters`.
2. **Авторизация**: Система защищает маршрут и делает редирект на страницу входа: `/login?returnTo=%2Fmaster-onboarding%2Fstart`. Пользователь вводит номер телефона и проходит проверку по OTP-коду.
3. **Мост маршрутизации (Bridge)**: 
   - После успешного входа пользователь перенаправляется на системный маршрут `/master-onboarding/start`.
   - В этот момент на экране отображается только индикатор загрузки (spinner). 
   - Под капотом отправляется API-запрос `POST /api/v1/me/master-onboarding/start`, который проверяет пользователя, регистрирует для него новый профиль мастера (или подхватывает существующий) и возвращает URL для дальнейшего редиректа (`/master-onboarding`).
   - Состояние пользователя в приложении обновляется (чтобы система учитывала новые права), и происходит автоматический переход в сам визард.
4. **Многоступенчатый Визард (`/master-onboarding`)**:
   Интерфейс представляет собой пошаговую форму с прогресс-баром (5 шагов):
   - **Шаг 1: Профиль (Обязательный)**. Ввод имени (обязательное поле) и информации "О себе". Без заполнения имени дальше не пустит.
   - **Шаг 2: Специализации (Обязательный)**. Выбор 1 или нескольких категорий услуг из выпадающего списка.
   - **Шаг 3: Услуги (Пропускаемый)**. Информационный шаг, подсказывающий, что услуги можно будет добавить позже из кабинета. (Шаг можно пропустить).
   - **Шаг 4: Расписание (Пропускаемый)**. Заполнение базового графика или пропуск шага.
   - **Шаг 5: Публикация**. Пользователю показывается превью его публичной карточки (имя + специализации). Кнопка «Опубликовать» становится активной.
5. **Завершение**: Нажатие кнопки вызывает конечный эндпоинт публикации `POST /master-dashboard/publish`, после чего система перенаправляет свежеиспеченного мастера в его рабочий кабинет — `/master-dashboard`.
