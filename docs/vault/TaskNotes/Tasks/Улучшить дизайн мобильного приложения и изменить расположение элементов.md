## TL;DR

Перестроить навигацию мобильного приложения: добавить таб **«Ещё»** (бургер) с разделами и переключателем «Кабинет мастера ↔ Кабинет салона ↔ Мой профиль». «Мой профиль» — последний пункт. Сейчас в навигации 4 таба и нет точки входа в профиль/смену кабинета.

## Текущее состояние (`mobile/app/(tabs)/_layout.tsx`)

Видимые табы: `index` (Сегодня), `calendar`, `records`, `clients`. Скрыты (`href: null`): `appointments`, `services`, `notifications`, `profile`. Уведомления и услуги фактически недоступны из таб-бара. Переключения между ролями нет — `useMeQuery` возвращает `effectiveRoles`, но UI его не использует для смены контекста (только `isAdmin` фильтр в `calendar.tsx:35`).

Скоуп мобайла зафиксирован в memory `project_mobile_app_scope.md`: одно приложение для master + salon_admin, потребительский UX вне скоупа.

## Что сделать

### 1. Перестройка таб-бара (5 табов)

Целевой набор:
1. **Сегодня** (`index`) — без изменений
2. **Календарь** (`calendar`)
3. **Записи** (`records`)
4. **Клиенты** (`clients`)
5. **Ещё** (новый таб, иконка `dots-horizontal` или `menu`)

### 2. Экран «Ещё» (`mobile/app/(tabs)/more.tsx`)

Контент сверху вниз:

- **Карточка-переключатель «Активный кабинет»** (если `effectiveRoles.salonMemberships.length > 0` И `masterProfileId` присутствует):
  - «Кабинет мастера» (radio/segmented)
  - «Кабинет салона <Название>» (если несколько — список)
  - Пишет выбор в `activeContext` (новый persisted store, аналог веба `getActiveSalonId()` + явное «mode = master | salon_admin»). Дефолт по правилам: один membership → salon, без membership → master, оба → последний выбранный.
  - Все API-запросы переключаются: master-режим → `/api/v1/master-dashboard/*`, salon-режим → `/api/v1/dashboard/*` с `X-Salon-Id`.
- **Раздел операций** (контент зависит от активного кабинета):
  - master: «Услуги», «Финансы», «Расписание», «Уведомления», «Приглашения от салонов»
  - salon_admin: «Услуги», «Расписание», «Персонал» (owner only), «Уведомления»
- **Раздел приложения**: «Тема», «Язык», «Безопасность» (биометрия), «Помощь / FAQ»
- **Мой профиль** — последний пункт (открывает существующий `profile.tsx`, его убираем из скрытых)
- **Выйти** — отдельной кнопкой в подвале

### 3. Адаптация контента табов под активный кабинет

- `index` (Сегодня): для master — личные записи + статы дня; для admin — записи салона.
- `calendar`: уже читает `isAdmin`, но не учитывает осознанное переключение. Привязать к `activeContext`, а не к наличию роли.
- `records`/`clients`: тот же принцип — фетчить из соответствующего namespace.

### 4. Аналог веба

На вебе уже есть похожая логика: `UserMenu` использует `effectiveRoles.salonMemberships`, есть `dashboardPath` / `dashboardSectionPath` и `activeSalonId` в `localStorage`. Перенести идею, но без дублирования кода — на мобайле свой store (Zustand уже подключён).

### 5. Дизайн

- Переключатель кабинета — компактный сегментед-контрол, чтобы не выглядел как отдельная страница.
- Иконки SF Symbols / Material Community (уже используется `@expo/vector-icons`), без эмодзи.
- Учесть safe area (вверх и вниз) — на iPhone X+ профиль не должен прятаться за home indicator.
