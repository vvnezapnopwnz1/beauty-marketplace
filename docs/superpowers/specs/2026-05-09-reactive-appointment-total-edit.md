# Спек: реактивная стоимость при редактировании записи

## Контекст

В деталях записи салонного дашборда поле «Итого» предзаполняется из сохранённого `totalCents`, но не реагирует на изменение выбранных услуг в форме редактирования. Из-за этого пользователь добавляет или удаляет услуги, а стоимость до сохранения остаётся старой; после сохранения UI также может выглядеть устаревшим, пока drawer не получит свежие данные.

Backend уже поддерживает модель `base(line_items) + manual_delta`: если сумма рассчитана автоматически, изменение услуг пересчитывает итог; если сумма изменена вручную, при изменении услуг сохраняется ручная дельта.

## Цель

Сделать форму редактирования записи реактивной: пользователь видит будущую стоимость сразу при добавлении/удалении услуг и при ручном вводе суммы, до нажатия «Сохранить».

## Правила поведения

1. Для записи с `totalSource = calculated` изменение выбранных услуг сразу обновляет поле «Итого» до суммы выбранных услуг.
2. Для записи с `totalSource = manual` изменение выбранных услуг сохраняет ручную дельту: `итог = сумма выбранных услуг + manualDeltaCents`, минимум `0`.
3. Ручной ввод в поле «Итого» переключает локальное состояние формы в manual-режим и пересчитывает `manualDeltaCents = введённый итог - сумма выбранных услуг`.
4. Действие «Сбросить к сумме услуг» сбрасывает итог к текущей сумме выбранных услуг, а не к старому `appointment.calculatedTotalCents`.
5. При сохранении frontend отправляет `totalCents` только в manual-режиме. В calculated-режиме `totalCents` не отправляется, чтобы backend сам сохранил рассчитанный итог по `serviceIds`.

## Архитектура frontend

Основной файл: `frontend/src/pages/dashboard/ui/drawers/AppointmentDrawer.tsx`.

Добавить локальную модель цены формы:

- `priceMode: 'calculated' | 'manual'`;
- `manualDeltaCents: number`;
- `selectedServicesTotalCents`, вычисляемый из `services` и `serviceIds`;
- helper `clampTotalCents(value)` для защиты от отрицательных итогов.

При `resetFromAppt`:

- `serviceIds` берутся из detail `services` или legacy `serviceId`;
- `selectedServicesTotalCents` на этом этапе может быть недоступен, поэтому дельта считается от `a.calculatedTotalCents ?? 0`;
- если `a.totalSource === 'manual'`, `manualDeltaCents = editableTotal - calculatedTotal`;
- иначе `manualDeltaCents = 0`, `priceMode = calculated`.

При изменении услуг:

- обновить `serviceIds`;
- посчитать новую сумму выбранных услуг по уже загруженному списку `services`;
- если `priceMode === calculated`, установить `totalCents = newBase`;
- если `priceMode === manual`, установить `totalCents = max(0, newBase + manualDeltaCents)`.

При ручном вводе стоимости:

- `priceMode = manual`;
- `totalCents = parsedValue`;
- `manualDeltaCents = parsedValue - selectedServicesTotalCents`.

## UX

- Поле «Итого (₽)» остаётся редактируемым.
- Если локальный итог отличается от текущей суммы выбранных услуг, показывается ссылка «Сбросить к ... ₽».
- В блоке просмотра «Итого» можно продолжать показывать сохранённый `appointment.totalCents`; реактивное значение отображается в форме редактирования.

## Тестирование

Минимальная проверка:

- unit/RTL-тест для helper-логики цены, если рядом есть подходящее тестовое окружение;
- иначе покрыть чистые helpers через Vitest в отдельном файле рядом с drawer или в `shared/lib`;
- manual smoke: открыть запись, добавить услугу, увидеть изменение «Итого» до сохранения; изменить сумму руками, добавить услугу, увидеть сохранение дельты.

## Не входит

- Изменение backend-контракта.
- Изменение master-dashboard/mobile.
- Отдельные поля «Скидка», «Надбавка», «Предоплата».
